## 1. プロダクト概要

### 1.1 OrbitXとは
OrbitXは、X（旧Twitter）のコンテンツ作成・管理・分析を一元化したAI搭載のソーシャルメディアマネジメントプラットフォームです。

### 1.2 主な価値提案
- **AI投稿生成**: 過去のバズ投稿を分析し、構造を模倣した新規投稿を自動生成
- **ティア別管理**: いいね数に基づくS/A/B/Cティア分類で投稿パフォーマンスを可視化
- **予約投稿**: AIによる最適投稿時間の提案と週間カレンダー管理
- **外部コンテンツ活用**: Qiita、Zenn、GitHubなどからネタ収集

### 1.3 技術スタック
| カテゴリ | 技術 |
|---------|------|
| フロントエンド | Next.js 16.1.4、React 19、TypeScript 5、Tailwind CSS 4 |
| バックエンド | Next.js API Routes |
| データベース | Firebase Firestore |
| 認証 | Firebase Auth（Google）、X OAuth 2.0 PKCE |
| AI | OpenAI GPT-4o / GPT-4o-mini、Perplexity API |
| ホスティング | Vercel |

## 3. 詳細機能仕様

### 3.1 ダッシュボード (`/dashboard`)

#### 機能
- **統計カード**: 総投稿数、総インプレッション、総いいね、S tier数、A tier数

- **投稿履歴タイムライン**: 投稿日時、元投稿情報

#### データソース
- Firebase: `users/{uid}/posts`、`users/{uid}/scheduledPosts`
- localStorage: 目標設定

### 3.2 AI投稿生成 (`/compose/generate`)

#### フロー
1. **投稿内容入力**: ユーザーが投稿したい内容をテキストで入力
2. **URL入力（任意）**: 参考リンクを追加
3. **参考投稿ソース選択**:
   - 過去投稿一覧（自分の投稿）
   - 他者バズ投稿
   - AIおまかせ
4. **カテゴリー選択**（AIおまかせ以外は必須）
5. **情報自動補足**（オプション）:
   - ONにすると検索クエリを生成
   - ユーザーがクエリを選択
   - Deep Researchで5000文字以上の情報取得
6. **6パターン生成**: 選択した参考投稿の構造を模倣
7. **パターン選択**: 気に入った投稿を選んで編集画面へ

#### カテゴリー一覧（11種類）
1. 速報・ニュース系
2. Tips・ノウハウ系
3. 記事・コンテンツ紹介系
4. ツール・サービス紹介系
5. 動画・メディア紹介系
6. プロンプト・AI活用系
7. プロダクト・リリース系
8. イベント・登壇系
9. プレゼント・キャンペーン系
10. 採用・メンバー募集系
11. 日常・つぶやき系

#### 情報自動補足機能

##### 検索クエリ生成（最新実装）
- **Perplexity API**でリアルタイムWeb検索を実行
- 投稿内容からキーワードを抽出
- 実際に検索して見つかった情報を元に具体的なクエリを生成
- 抽象的なクエリ（「〇〇 最新情報」）は禁止
- 具体的な情報（機能名、バージョン、日付）を含むクエリのみ

##### Deep Research
- 選択したクエリで詳細リサーチ
- 5000文字以上の包括的な情報を収集
- 日付認識で直近2週間の情報を優先
- クエリ分配: 1クエリ→6パターン、2クエリ→3ずつ、3クエリ→2ずつ

#### カードアクション（生成後）
| ボタン | 機能 |
|--------|------|
| AI強化 | 現在の投稿を3パターンで強化 |
| ファクトチェック | 事実確認と流れの整合性チェック |
| AI補正 | バズるプロンプトを使って3パターン補正 |
| 編集 | エディター画面へ遷移 |
| 予約 | 予約投稿モーダルを開く |

### 3.3 AI補正機能（最新実装）

#### 概要
生成された投稿の一貫性と有益さを高める機能。過去のS tier投稿から抽出した「バズるプロンプト」を使用。

#### バズるプロンプト作成（過去投稿一覧ページ）
1. S tier投稿が3件以上ある場合、「S tier投稿からバズるプロンプト作成」ボタンが表示
2. クリックすると以下を分析・抽出:
   - **3パターンのバズる構造**（テンプレート付き）
   - **バズる投稿の特徴**（5項目）
   - **避けるべきパターン**（3項目）
   - **使える表現例**（5個）
3. Firestoreに保存（`users/{uid}/settings/buzzPrompt`）
4. 再生成ボタンで更新可能

#### AI補正の動作
1. カードの「AI補正」ボタンをクリック
2. バズるプロンプトがある場合、そのパターンを使用
3. 3パターンの補正版を生成:
   - バズるプロンプトの3パターンに基づく
   - またはデフォルト（一貫性強化、具体性追加、フック強化）
4. モーダルで比較・選択
5. 適用すると元のカードに反映

#### 補正のポイント
- 構造（行数、改行、箇条書き）は維持
- 違和感のある箇所は積極的に修正・削除
- 「で、結局何？」とならない一貫性を確保
- temperature 0.6で多様性を確保

## 4. API仕様

### 4.1 認証系

#### `GET /api/auth/x`
X OAuth 2.0 PKCE認証開始
- PKCE code_verifier/challenge生成
- state（CSRF対策）生成
- X認証画面へリダイレクト

#### `GET /api/auth/x/callback`
OAuth 2.0コールバック
- トークン交換
- Firestoreに保存
- 設定画面へリダイレクト

#### `POST /api/auth/x/disconnect`
X連携解除
- トークン削除

### 4.2 投稿生成系

#### `POST /api/generate`
AI投稿生成
```typescript
// リクエスト
{
  mode: "reference" | "imitate" | "template",
  content: string,
  referenceText?: string,
  templateId?: string,
  category?: string,
  tone?: string,
  researchData?: string,
  queryAxis?: string
}

// レスポンス
{
  success: boolean,
  text: string
}
```

#### `POST /api/generate/search-queries`
検索クエリ生成（最新実装）
```typescript
// リクエスト
{
  content: string,
  postCategory?: string,
  postSource?: string,
  today: string // "2026-01-25"形式
}

// レスポンス
{
  success: boolean,
  queries: [{
    query: string,
    category: string,
    description: string,
    source: string
  }],
  dateRange: { from: string, to: string },
  webSearchUsed: boolean
}
```

#### `POST /api/generate/deep-research`
詳細リサーチ
```typescript
// リクエスト
{
  content: string,
  queries: string[],
  today: string
}

// レスポンス
{
  success: boolean,
  research: string, // 5000文字以上
  totalChars: number
}
```

#### `POST /api/generate/ai-correct`
AI補正（最新実装）
```typescript
// リクエスト
{
  currentText: string,
  originalContent: string,
  referenceText: string,
  researchData?: string,
  buzzPrompt?: {
    prompt: string,
    patterns: [{name, description, template}],
    characteristics: string[],
    avoidPatterns: string[],
    samplePhrases: string[]
  }
}

// レスポンス
{
  success: boolean,
  patterns: [{
    type: string,
    text: string,
    changes: string,
    structureValid: boolean
  }],
  buzzPromptUsed: boolean
}
```

#### `POST /api/generate/analyze-buzz`
バズる投稿分析（最新実装）
```typescript
// リクエスト
{
  posts: [{
    text: string,
    likes: number,
    tier: string
  }]
}

// レスポンス
{
  success: boolean,
  buzzPrompt: {
    prompt: string,
    patterns: [{name, description, template}],
    characteristics: string[],
    avoidPatterns: string[],
    samplePhrases: string[],
    analyzedPosts: number,
    avgLikesAnalyzed: number
  }
}
```

#### `POST /api/generate/fact-check`
ファクトチェック
```typescript
// リクエスト
{
  content: string,
  originalContent: string,
  referenceText: string
}

// レスポンス
{
  wasModified: boolean,
  correctedContent?: string,
  summary: {
    totalClaims: number,
    accurateClaims: number,
    inaccurateClaims: number,
    flowIssues: number
  }
}
```

## 7. ユーザーフロー

### 7.1 初回セットアップ
1. Googleアカウントでログイン
2. X連携（OAuth認証）
3. CSVインポート（過去投稿）
4. バズるプロンプト作成（S tier投稿分析）

### 7.2 投稿作成フロー
1. `/compose/generate` で内容入力
2. カテゴリー選択
3. 情報自動補足ON（任意）
4. 検索クエリ選択 → リサーチ実行
5. 6パターン生成
6. AI補正で調整（任意）
7. エディターで最終編集
8. 投稿 or 予約

### 7.3 分析フロー
1. `/posts` で過去投稿確認
2. ティア別フィルタでハイパフォーマーを特定
3. 構造分析でパターン把握
4. バズるプロンプト作成で知見を抽出

## 8. 制約・ルール

### 8.1 投稿生成ルール
- 絵文字は参考投稿にある場合のみ使用
- 「！」は最小限（1-2個まで）
- AIっぽい表現は禁止:
  - 「〜ですね」「〜しましょう」
  - 「素晴らしい」「画期的」「必見」「ぜひ」
- URLは投稿に含めない（後でユーザーが追加）

### 8.2 ティア判定ルール
| ティア | いいね数 | 説明 |
|--------|---------|------|
| S | 200+ | 同文再投稿OK |
| A | 100-199 | 構文模倣推奨 |
| B | 50-99 | 参考程度 |
| C | <50 | 保存のみ |

### 8.3 情報自動補足ルール
- カテゴリー選択が必須（AIおまかせモードを除く）
- 検索クエリは具体的な情報を含む（抽象的なクエリ禁止）
- リサーチは直近2週間の情報を優先
- 5000文字以上の包括的な情報を収集
